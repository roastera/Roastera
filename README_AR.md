# ROASTERA | متجر القهوة

مشروع React + Vite + Supabase، بتصميم عربي RTL وألوان أخضر داكن وكريمي وذهبي.

## مهم قبل الإطلاق
- المنتجات والأسعار الموجودة أمثلة تجريبية، عدّلها قبل استقبال طلبات حقيقية.
- الموقع لا يجمع دفعات إلكترونية. الزبون يسجّل الطلب ثم يفتح واتساب لتأكيده يدوياً.
- البريد `roastera.aleppo@gmail.com` ظاهر للتواصل فقط. لا يوجد إرسال بريد تلقائي مفعّل في هذا الإصدار.
- لا تضع Supabase `service_role` key في الموقع أو GitHub. الموقع يحتاج فقط URL و anon/publishable key.
- لوحة الإدارة تقبل تسجيل الدخول لحساب Supabase Auth الذي بريده `roastera.aleppo@gmail.com`. لا يوجد حساب أو كلمة مرور افتراضية.

## 1) إنشاء قاعدة البيانات
1. أنشئ مشروعاً جديداً في https://supabase.com/
2. افتح SQL Editor.
3. انسخ محتويات `supabase/schema.sql` كاملة والصقها ثم اضغط Run.
4. من Authentication > Users أنشئ/أضف مستخدم الإدارة ببريد `roastera.aleppo@gmail.com` وكلمة مرور قوية. إذا استخدمت رسالة دعوة، أكمل التحقق أولاً.
5. في Project Settings > API أو Connect انسخ Project URL و anon/public/publishable key.

## 2) تشغيل الموقع محلياً
تحتاج كمبيوتر أو بيئة تطوير سحابية تدعم Node.js:
1. فك ضغط المشروع.
2. أنشئ ملف `.env` في جذر المشروع، محتواه:
   `VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co`
   `VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY`
3. نفّذ `npm install` ثم `npm run dev`.
4. افحص الموقع، وأنشئ طلب اختبار.

## 3) رفع المشروع من الموبايل عبر GitHub
أسهل طريقة للموبايل: استخدم GitHub في المتصفح وأنشئ repository جديداً، ثم ارفع الملفات/المجلدات من نسخة ZIP بعد فكها. بعض واجهات GitHub على الهاتف لا تتيح رفع مجلد كامل بسهولة؛ إذا واجهت ذلك، افتح github.dev أو استخدم بيئة تطوير سحابية مثل CodeSandbox/StackBlitz التي تستورد GitHub repository.
لا ترفع ملف `.env` أو أي مفاتيح سرية. ملف `.env.example` للتوضيح فقط.

## 4) النشر المجاني
يمكنك نشر المشروع على Vercel أو Netlify بالخطة المجانية المناسبة:
- Build command: `npm run build`
- Output directory: `dist`
- أضف Environment Variables التالية في إعدادات المشروع:
  - `VITE_SUPABASE_URL` = رابط مشروع Supabase
  - `VITE_SUPABASE_ANON_KEY` = المفتاح العام anon/publishable
- ثم Deploy.
- بعد كل تغيير في GitHub، أعد النشر تلقائياً أو يدوياً.

## 5) اختبار الطلب
1. افتح الموقع المنشور.
2. أضف منتجاً للسلة وأكمل نموذج الطلب.
3. لا يعتبر الطلب محفوظاً إلا إذا ظهرت رسالة نجاح ورقم طلب صادر من قاعدة البيانات.
4. افتح واتساب وأرسل الرسالة بنفسك لتأكيد الطلب.
5. افتح لوحة الإدارة وسجّل الدخول ببريد المالك، ثم تأكد من ظهور الطلب.
6. جرّب أن تفتح لوحة الإدارة من نافذة غير مسجّلة، وتأكد أن بيانات الطلبات لا تظهر.

## 6) الأمان وحدود النسخة
- RLS يمنع الزوار من قراءة الطلبات مباشرة؛ إنشاء الطلبات يتم من خلال دالة SQL تتحقق من المنتجات والأسعار على الخادم.
- عدّل سعر المنتجات ومخزونها من لوحة الإدارة بعد تسجيل الدخول.
- تحقق من سياسات Supabase واختبرها قبل إعلان الموقع للناس.
- هذا المشروع لا يرسل بريد إشعار تلقائي، ولا يرسل واتساب تلقائياً. واتساب يفتح رسالة مجهّزة ويحتاج ضغط المستخدم على إرسال.
- لا يوجد بوابة دفع إلكتروني.
- الأسعار التجريبية لا تمثل أسعاراً حقيقية أو توصية تجارية.
